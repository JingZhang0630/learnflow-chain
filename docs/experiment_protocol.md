# LearnFlow-Chain Experiment Protocol (frozen before any experiment is run)

Version: 1.0 — 2026-10-18. Any departure from this document after the freeze commit is recorded in
`docs/deviations.md` with date, reason and affected results. Results that depend on a deviation are
labelled as such in the paper.

## 0. Global settings

- Master seed: `20261018`. Per-run seeds: `20261018 + r`, r = 0..4 (five repetitions) unless stated.
- Hardware/software is recorded automatically into `results/env.json` (CPU, RAM, OS, Python and package versions, Docker and Fabric versions).
- All raw metrics are written as CSV/JSON under `results/`; every figure and table is generated by a script under `experiments/` from those files. Failed runs are kept and reported.
- No real LearnFlow user data is used. Real data = two public datasets below; everything else is synthetic.

## 1. Datasets and institution partitions

**D1 ASSISTments 2009–2010 skill builder (corrected).** Source file `assist09_corrected.csv` (read-only).
Keep `original == 1`; deduplicate by `order_id` (keep first row). Institutions = the 10 schools (`school_id`) with
at least 5,000 remaining responses. Items = `problem_id` with at least 20 responses inside these schools;
students with at least 5 responses on kept items. Students never span schools (verified: 0 users in >1 school).

**D2 Junyi Academy (2018–2019 public release).** `Log_Problem.csv` joined with `Info_UserData.user_city`.
Item = exercise `ucid`; a response = one `Log_Problem` row (`is_correct`). Institutions = the 10 cities with the
most responses (rows with empty city dropped). Items with ≥ 50 responses; students with ≥ 10 responses.
External difficulty label: `Info_Content.difficulty` (easy / normal / hard; unset rows excluded).

**D3 Synthetic Rasch.** Ground-truth item difficulty `b_i ~ N(0,1)`, I = 500 items. Ability
`θ_u ~ N(μ_k, 1)` for a student of institution k. Each student answers 40 items. Two regimes:
- IID: μ_k = 0 for all k; every institution samples items uniformly from all 500.
- non-IID: μ_k evenly spaced in [−1, 1]; institution k samples items from a window of 250 items whose centre
  is shifted by k (item exposure overlaps only partially between institutions).
Configurations: K ∈ {3, 10}, 300 students per institution. D3 is the **only** data used to choose
hyper-parameters (Section 3); D1 and D2 are evaluated with the frozen values.

**Split.** For every student, responses are split 80/20 into train/test at random (seeded). Abilities and
difficulties are fitted on train only.

## 2. Methods (Experiment A)

All Rasch fits maximise `Σ log σ(±(θ_u − b_i)) − λ/2 (‖θ‖² + ‖b‖²)` with λ = 1 (fixed, Gaussian prior N(0,1)).

- **CEN** Centralised Rasch on pooled train data (reference only; it requires pooling raw data).
- **LOC** Local Rasch per institution; an item unseen locally gets b = 0 (prior mean).
- **CNT** Distributed counts: each institution shares per-item (correct, total); `b_i = −logit((c_i+1)/(n_i+2))`.
- **FED** Federated Rasch: the server holds b; each round every institution (i) updates local θ given b
  (a fixed number of Newton steps), (ii) sends the gradient and Hessian diagonal of its log-likelihood w.r.t. b.
  The server applies a damped Newton step. θ never leaves the institution.
- **DP-FED** FED with student-level differential privacy (Section 4); server uses gradient steps (no Hessian is released).

Prediction for a test response: `p = σ(θ_u − b_i)` with the student's own (local) θ.

**Metrics.** D3: MAE and RMSE of b against true b over all items (both centred to mean 0). D1/D2: test AUC,
Brier score and log-loss (pooled and per institution); RMSE and Spearman ρ of b against CEN (reference,
not ground truth). D2 additionally: Spearman ρ between b and the expert label (easy=0, normal=1, hard=2).
Mean ± s.d. over five seeds (seeds change the split and, for DP, the noise).

## 3. Hyper-parameter selection (D3 only)

FED: rounds T_fed, local Newton steps, damping. DP-FED: rounds T, clipping norm C, server learning rate η.
Selected on D3 non-IID K = 10, seed 20261018 only, by lowest b-RMSE at ε = 2; the chosen values are written to
`results/hparams_frozen.json` and committed **before** D1/D2 are run. No D1/D2 test metric is inspected during selection.

## 4. Differential privacy (Experiment B)

- Privacy unit: one **student** (all responses of the student). Neighbouring datasets differ by adding/removing one student.
- Per round each institution computes each student's contribution to the gradient w.r.t. b, clips it to
  L2 norm C, sums, and adds `N(0, σ²C²I)` before sending. θ is local and never released.
- Accounting: each round is a Gaussian mechanism with sensitivity C ⇒ ρ = 1/(2σ²) zCDP per round,
  ρ_total = T/(2σ²); ε(δ) = ρ_total + 2·sqrt(ρ_total·ln(1/δ)). δ = 1e−5. Given target ε, σ is solved exactly.
- Budget ledger: (task, institution, mechanism, ε, δ, C, σ, T) is recorded per run; a task whose request would
  exceed the institution's remaining budget is refused before the round starts (fail-closed; tested).
- Grid: ε ∈ {0.5, 1, 2, 4, 8} plus non-private FED. Reported: utility metrics of Section 2, wall-clock time, bytes sent.

## 5. Access control (Experiment C)

Policy decision (evaluated at join, before **every** round, and at result release):
`allow = identity valid ∧ role permits action ∧ resource in grantor's scope ∧ task purpose = grant purpose ∧ now < expires_at ∧ grant not revoked ∧ task state permits action ∧ output type allowed for role`.

- **C1 conformance and differential test.** 10,000 random requests (seeded) over roles × actions × purposes ×
  grant states × task states, including the eight attack cases of the design document. Each is decided by the
  backend PDP and by the chaincode on Fabric; reported: agreement rate and per-case outcome.
- **C2 enforcement models under mid-task events.** 200 simulated federated tasks (K = 10, 20 rounds), in each a
  random subset of grants is revoked or expires at a random round. Compared: (a) login-only RBAC,
  (b) check at task join only, (c) LearnFlow-Chain per-round re-evaluation. Metrics: number of unauthorized
  round participations, false denials, revocation-to-effect latency (rounds and seconds).
- **C3 tamper detection.** 1,000 off-chain artefacts (result files and Merkle leaves); one random byte flipped in
  each; metric: detection rate and verification time.

## 6. Ledger anchoring performance (Experiment D)

Fabric test network (fabric-samples `test-network`, v2.5.x): 2 organisations × 1 peer, 1 Raft orderer,
default endorsement policy and block cutting parameters (recorded). Chaincode: `learnflow_audit` (JavaScript).
- Anchoring strategies: per-record transaction vs Merkle batch with batch size B ∈ {10, 100, 500, 1000}.
- Workload: audit/event records derived from D2. Each configuration submits for a fixed 120 s (after 15 s warm-up)
  at a fixed client concurrency of 16, repeated 3 times.
- Metrics: records/s and tx/s (committed), submit-to-commit latency P50/P95, ledger growth (bytes in the peer's
  block store), peer/orderer CPU and memory (docker stats sampling every 1 s), error rate.
- Big-data pipeline: Merkle manifest construction over the full D2 log (time, throughput, tree depth, proof size,
  proof verification time). Anchoring time for the full log under each strategy is **extrapolated** from the
  measured throughput and labelled as an extrapolation.

## 7. What will not be claimed

Blockchain records prove integrity and order of registered digests, not truthfulness of data or correctness of
conclusions. "Data stays local" is not a privacy guarantee; only DP-FED with the accounting above is called
differentially private. Revocation stops future controlled access; it does not retract copies. No educational or
causal effect is claimed.
